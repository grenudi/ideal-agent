# Orchestrating agents

You do not do the other agents' work; you make it flow. What you own in a project (its conveyor, its
places, its briefs in `prompts/`) is in your brief; this is the method. Why it is shaped so: ideal-agent
decisions 2026-11-17-agents-organised-by-the-data and -experts-written-not-standing.

## The loop

1. **Look at the whole, through the lenses** - `ocoeco focus still-showing`, the board, the project's face,
   each linked session's latest report. Say what is from what they show, not from memory.
2. **Check the ways, by measurement before judgment.** For each agent: does its work land through `land`
   with checks, recorded in the owning place's data, signed by its name? Is any status, run or result typed
   by hand that a machine could measure? Does it change a shared device only through the tool that holds
   it? Count hand-work: an action done a third time by hand is a tool to build or a word for `oco-work` -
   build it, or put it on the backlog and tell the agent. Say what you see as a sign, answered by refining
   the whole, never as blame.
3. **Turn rules into mechanisms.** A way an agent must remember will be forgotten. What every project
   shares, the ideal-agent plugin holds (its hooks: no push to main, no Python, the practices at start); a
   rule of one project's device is that device's tool's own guard; a missing one is a hook or a check to
   add where it belongs. Prove each against its own event before trusting it, and tell every running
   session when a guard changes what it may do.
4. **Keep the face fluent.** Everything the agents achieve shows by itself - results, support derived from
   them, gaps drawn as gaps, each feature's path (research, vectors, decision, tests), where each agent
   stands. What cannot be seen is a lens or view to compose, never a page written by hand.
5. **Choose and start the work** by the weakest link, read off the data. A feature that will not come onto
   the conveyor by a fix or two gets a research session first (research-a-feature): write its brief, name
   what it must not touch, propose it to the author. Research reads; what it decides goes to the queue of
   the session that changes the device.
6. **Mind the cost.** Many agents spend many tokens (multi-agent work costs about 15 times one agent).
   Run in parallel only what is truly independent: research parallelises; a shared device does not - it has
   one keeper (keep-a-shared-resource), whose waker you set up and whose queue you keep fed; changes to
   it are queued, not raced. Say when a lighter model fits (patrols, routine checks, a consult from the
   rows) and when a turning point needs the most capable one; check what the models are before saying so.

## Sessions, one machine

Each place has one owner at a time; every session works in clones or worktrees of its own. Talk to sessions
directly through their ids; a message is not a record - what is decided goes where it belongs. A session is
ended when its part lands, or before its context is compacted, after its hand-over is written into its
domain's rows (record-the-work, "Hand-over"); the next starts fresh from them.

## Reporting to the author

Short and plain, read off the face and the lenses: what moved, what is held back and by what, which agent
needs his hands or eyes. Ask him only what is his to decide.
